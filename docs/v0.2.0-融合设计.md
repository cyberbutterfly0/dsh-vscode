## 1. 定位

一句话：**自绘聊天负责"在编辑器里顺手干活"，完整 dsh 界面负责"看全貌"，两者共用一条连接。**

0.1.0 已经把这套骨架搭完并真机验证。0.2.0 **不推翻它**，只做三件事：

1. 把本轮改动从"面板内红绿卡片"升级成 **VS Code 原生并排 diff**；
2. 把完整 dsh 界面从"能开"升级成 **能缩放、能多开、能回跳**；
3. 把 runtime 管理从"能用"补到 **"换机器也能用"**。

## 2. 三条主线

| 主线 | 内容 | 为什么是它 |
| --- | --- | --- |
| **A. 原生 diff** | 本轮改动 → `vscode.diff` 左右并排，带 VS Code 自己的跳转/折叠/复制 | 用户看代码的地方就是 diff，卡片永远差一截 |

**明确不做**（防止自由发挥）：

- 不引入任何 `@deepseek-ai/*` 依赖；
- 不重写 dsh 前端；
- 不做 VS Code 原生 chat participant（`chatParticipants` 那套跟 dsh 的 agent 循环不兼容）；
- 不做远程/代理/隧道；
- 不往 Marketplace 发（保持 `publisher: local`，private vsix）。

## 5. P0：原生并排 diff

### 5.1 数据源（现成的，不用自己还原）

dsh 已经把 diff 算好了，端点已封装在 `src/dsh/api.ts:206-218`：

| 端点 | 参数 | 返回 |
| --- | --- | --- |
| `/api/changes.summary` | `sessionId`, `seq` | `WorkspaceChangesSummary`（`src/dsh/types.ts:301-310`） |
| `/api/changes.diff` | `sessionId`, `seq`, `index` | `WorkspaceFileDiff`（`src/dsh/types.ts:312-340`） |

关键字段：

```ts
interface WorkspaceDiffHunk {
  oldStart: number; oldLines: number;
  newStart: number; newLines: number;
  lines: string[];   // 每行带 '+' / '-' / ' ' 前缀
}

interface WorkspaceFileDiffText {
  kind: 'text';
  path: string;      // 工作区内是相对路径，区外是绝对路径
  display: string;
  before: boolean;   // 本轮之前是否存在
  after: boolean;    // 本轮之后是否存在
  hunks: WorkspaceDiffHunk[];
  coarse: boolean;   // true = 行级对比不可用，只有整体替换
}
```

`WorkspaceChangesSummary.snapshot?: { before: string; after: string }` —— **这个字段第一步就要实测**。如果它是全量文本，§5.2 整段可以跳过，直接喂给 `vscode.diff`。如果它是别的东西，按 §5.2 走。

> **不要学 dsh-native-panel 去扫 session log 反向还原 before-image。** 它那么做是因为没有 `/api/changes.diff`。我们有，直接用。

### 5.2 重建 before/after 文本

三种情况，按优先级：

**(1) 本轮刚结束（最常见）**——磁盘上的文件就是 after。

```
afterText  = 读磁盘（diff.path）
beforeText = 对 afterText 反向应用 hunks
```

反向应用：从后往前遍历 hunks，把 `+` 行删掉、把 `-` 行插回 `oldStart` 位置；`before: false` 时 beforeText = `''`。

**(2) 历史轮次，或文件在本轮之后又被改过**——磁盘已经不是当时的 after，反推会错。

降级为「**hunk 片段视图**」：只把 hunk 区域分别写成两个虚拟文档。行号不对但内容对比是真的，够看。标题后缀 `（片段）`。

**(3) `coarse: true`**——没有 hunks。等价于整体替换：

- `before: false` → before 为空
- `after: false` → after 为空
- 否则 before/after 都是"整文件"，此时**没有内容可对比**，只能提示"该文件本轮整文件重写，行级对比不可用"（沿用 0.1.0 的文案，`src/chat/core.ts:682-710`）。

**(4) `kind: 'binary'` / `'oversized'`**——不生成 diff，点击提示原因。

### 5.3 虚拟文档

新建 `src/chat/diff-docs.ts`：

```ts
const SCHEME = 'dsh-diff';

// URI 形如：dsh-diff:/<绝对路径>?side=before&key=<sha1>
class DiffContentProvider implements vscode.TextDocumentContentProvider {
  provideTextDocumentContent(uri: vscode.Uri): string { /* 从内存 Map 取 */ }
}
```

- 内容存内存 `Map<string, string>`，key 用 `sessionId:seq:index:side`；
- `workspace.registerTextDocumentContentProvider(SCHEME, provider)`；
- 每个 diff 打开的文档要能被 GC：关闭 `onDidCloseTextDocument` 时删对应条目，或设 20 个上限 LRU。

### 5.4 打开方式

```ts
const title = `${display}（本轮改动）`;
await vscode.commands.executeCommand(
  'vscode.diff',
  beforeUri, afterUri, title,
  { preview: false, preserveFocus: false } as vscode.TextDocumentShowOptions,
);
```

入口：

- 改动卡片上每个文件名 → 点开原生 diff（替换现在的内联展开；**内联展开保留为"快速预览"**，右键菜单里另给"在编辑器中打开 diff"）；
- 卡片头部总按钮 → 打开**本轮全部文件**的 diff（`vscode.diff` 只能一次一个，用 `commands.executeCommand` 循环，或改成"改动列表 QuickPick → 选一个打开"）；
- 命令 `dsh: 打开本轮改动`（有当前会话/最近一轮时可用）。

### 5.5 新增协议消息

`src/protocol.ts` 已有 `{ type: 'load-diff', sessionId, seq, index }`（:202）。加两条：

```ts
| { type: 'open-native-diff'; sessionId: string; seq: number; index: number }
| { type: 'reveal-diff-file'; path: string }   // 在资源管理器里定位
```

## 7. P0：runtime 韧性

现状 `src/dsh/runtime.ts`（234 行）已实现 dsh 探测 + spawn + 从 stdout 抓 `dsh web:` 行。要补的：

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `dsh.startTimeoutMs` | `45000` | spawn 后等 URL 的上限。0.1.0 的 STATUS 记了"22 个第三方插件时 15s 起，赶上抢锁能拖到数分钟"，45s 是合理值 |
| `dsh.stopOnExit` | `true` | 扩展停用时杀自己 spawn 的 dsh。`attach` 模式永远不杀 |
| `dsh.launchPreference` | `auto` | `auto` / `npm` / `desktop`。`desktop` 走用户配的 `dsh.desktopCommandPath` |
| `dsh.env` | `{}` | spawn 时追加的环境变量（代理、`DSH_HOME` 等） |

`dsh.stopOnExit` 要小心：如果用户是 `mode: auto` 且复用了别人的实例（凭据文件命中的），**不能杀**——只有自己 spawn 的才记录 pid 并可杀。现有 `client.ts` 的凭据里应该已经区分了来源，实现时确认。

**Desktop 启动**：`dsh-native-panel` 有 `dsh.desktopCommandPath` 但命令格式未知。实现顺序：

1. `launchPreference: npm` → 用现有探测链（`cliPath` → PATH → npm 全局 → npx 缓存）；
2. `desktop` → 只试 `desktopCommandPath`，失败直接报错，不回落；
3. `auto` → 先 npm，npm 找不到再试 desktop（有 `desktopCommandPath` 才试）。

**需实测**：DSH Desktop 到底暴露什么命令行入口。查不到就把 `launchPreference` 的 `desktop` 选项先藏起来（保留配置位，enum 里不放）。

### 7.1 验收

- [ ] 把 `dsh.startTimeoutMs` 设成 1000 → 明确报"启动超时，看日志"而不是卡死；
- [ ] `mode: spawn` + 关掉 VS Code → dsh 进程消失；

## 8. P1：bridge（默认关）

### 8.1 它解决什么

只解决两件自绘聊天做不到的事：

1. **完整 UI 里的文件链接能点回编辑器**（在 iframe 里点 `src/foo.ts:42` → VS Code 打开对应位置）；
2. **完整 UI 里能引用当前选区**（在 iframe 里按快捷键把编辑器选区塞进 dsh 的 composer）。

第 2 件对自绘聊天完全没用（我们自己就能带 `<editor-context>`）。所以 bridge 的**唯一不可替代价值是第 1 件**。

### 8.2 注入机制（需实测，这是本设计里最不确定的部分）

`dsh-native-panel` 的做法：往 `$DSH_HOME/profiles/<profile>/node_modules/dsh-vscode-bridge` 装一个包。**但它是怎么被 dsh 加载的，没有公开文档。**

三种可能，按优先级验证：

1. **cordis 自动扫描**：dsh 的 profile 目录如果有 `node_modules`，cordis 可能扫描并挂载。→ 装包后看 `dsh web` 启动日志里有没有出现包名。
2. **必须改 `package.json` 的 `dsh.profile.bundles`**：装包后 patch `~/.dsh/profiles/web/package.json` 把包名加进 bundles 数组。→ 这个动作会改用户环境，**必须在开关打开时才做，且卸载时精确移除**。
3. **都不可行** → bridge 降级为"不自动注入"，只保留一个命令让用户手动复制选区文本。

**如果 1 和 2 都要实测超过半天，直接放弃 bridge，0.2.0 不带它。** 代价只是"完整 UI 里文件链接不跳"，可接受。

### 8.3 扩展 ↔ bridge 的通信

bridge 在 dsh 进程内，扩展在 VS Code 进程内。可行的通路：

- **文件锁 + 轮询**（最土但最稳）：双方读写 `~/.dsh/dsh-vscode/bridge/<pid>.json`，200ms 轮询。dsh-native-panel 似乎就是这么干的。
- **Unix socket / loopback HTTP**：bridge 起一个 `127.0.0.1` 小服务，扩展连。跨平台麻烦（Windows 命名管道）。
- **复用 dsh 的 `/api`**：bridge 注册一个自定义 endpoint？——不保证能注册，dsh 的 endpoint 表是编译进去的。

**选文件锁**。消息格式：

```json
// 扩展写入（VS Code → dsh）
{ "type": "editor-state", "ts": 123, "file": "src/a.ts", "selection": {"start": {"line": 1, "character": 0}, "end": {"line": 5, "character": 0}}, "text": "…" }

// bridge 写入（dsh → VS Code）
{ "type": "open-file", "ts": 123, "file": "src/a.ts", "line": 42, "character": 8 }
```

### 8.4 开关与卸载

- 配置 `dsh.bridge.enabled`，默认 `false`；
- 打开时：检查包是否已装 → 未装则装 → 改 bundles（如需）→ 提示"重启 dsh 生效"；
- 关闭时：从 bundles 移除 → 删包目录 → 删 `bridge/` 目录；
- 命令 `dsh: 卸载 bridge`（`dsh-native-panel` 有 `uninstall` 脚本，参照它的清理范围）；
- **所有写用户目录的动作都要在 Output 面板留一行日志**（装了哪个路径、改了什么文件），否则出问题没法查。

### 8.5 验收

- [ ] 默认关，`~/.dsh/profiles/web/node_modules/` 下没有 `dsh-vscode-bridge`；
- [ ] 打开开关 → 装包 → 重启 dsh → 完整 UI 里点文件链接 → VS Code 打开对应行；
- [ ] 关闭开关 → 包被删干净 → `git status` 级别的检查（对比开关前的目录快照）无残留；
- [ ] dsh 升级后 bridge 不兼容 → 不崩，日志里一行警告。

| `dsh.stopOnExit` | boolean | `true` | 扩展停用时杀自己 spawn 的 dsh |

## 16. 风险与未决

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| `snapshot` 字段语义不明 | 决定 §5.2 要不要写反推逻辑 | **第一步实测**，一小时的事 |
| 历史轮次 diff 数据是否还能取到 | 决定是否需要"片段视图" | 实测 `/api/changes.diff` 对旧 seq 的返回 |
| bridge 加载机制未知 | 决定 bridge 做不做 | 半天验证，不通就砍 |
| dsh 升级改 `/api` 契约 | 扩展全挂 | 已签约"只用 HTTP/WS"，但无版本协商机制。可在启动时比对 `session/modelCatalog` 是否可用作为健康检查 |
| VS Code Webview iframe 跨域限制变化 | 完整 UI 打不开 | 已实测无 X-Frame-Options/CSP，但未来可能变 |
| 自绘 UI 与 dsh 前端行为漂移 | 用户觉得两边不一致 | 自绘只做四件套，复杂场景引导到完整 UI |

**两个问题留给用户拍板**（实现到那一步再问）：

1. 原生 diff 打开时，**内联卡片还留不留**？我建议留（快速扫一眼用），但这会让同一信息有两个入口。
2. bridge 如果验证不通，**是接受"完整 UI 里文件链接不跳"，还是花时间做"?** 我建议接受。

## 17. 与 dsh-native-panel 的逐项对照

| 能力 | 它 | 我们 0.2.0 |
| --- | --- | --- |
| 聊天界面 | 真实 dsh 页面（侧栏） | 自绘（tab + 侧栏）+ 完整 UI（tab） |
| 会话列表 | 无 | TreeView |
| 原生 diff | 扫 session log 反向还原 before-image | 用 `/api/changes.diff` 的 hunks，更直接 |
| 编辑器上下文 | bridge 自动注入 | `<editor-context>` 前缀（默认关）+ bridge（可选） |
| 文件链接回跳 | bridge 实现 | bridge 实现（同） |
| 缩放 | webview 内 zoomLevel | iframe CSS transform |
| runtime | autoStart / stopOnExit / launchPreference | 同 + attach 模式 |
| 代码规模 | 未知（0.3.0） | 0.1.0 约 9000 行，0.2.0 预估 +1500 行 |

**它的代码可以借的三处**（MIT，直接用）：

1. `bridge` 的**注入路径与卸载清理范围**（§8.2 那套目录结构）；
2. `zoomLevel` 的 **CSS 写法**（我们改成了 `calc(100%/zoom)` + `transform`，思路同）；
3. `uninstall.js` 的**清理清单**（哪些文件是它装的、卸的时候删哪些）。

**不借的**：它的 diff 反向还原（我们数据源更好）、它的"不做会话列表"（我们保留）、它的 secondary sidebar 定位（我们用编辑器 tab）。
